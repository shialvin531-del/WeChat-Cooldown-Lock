# WeChat Cooldown Lock · 微信冷静锁

可安装的本地 Android 应用，Kotlin、Jetpack Compose、MVVM、DataStore 和 Room。支持 Android 10（API 29）及以上，target SDK 36。包名 `local.wechat.cooldown`，版本 1.0.2，当前交付为调试签名测试版，可在签名相同的 1.0.0 上覆盖安装。

## 1.0.2 调整

- 修复查看冷静锁 App 后返回微信不计数的问题；保留外链返回的排除规则。累计进度与最近一次跳过原因分开显示，次数会随滚动窗口过期。
- 修复锁屏时收到微信前台事件后，解锁没有新事件时未恢复保护的问题。增强服务重连使用新会话，冷静到期后清除冷静期间的风险累计。
- 首页根据实际心跳显示增强保护运行状态，屏幕关闭与补充检测适当降频。

## 1.0.1 调整

- 移除紧急退出及应用内提前结束冷静的逻辑。冷静期内不显示暂停全部监测入口，设置操作也校验当前冷静计时；仍可返回桌面使用其他应用，到期自动结束。
- 修复晚到的 UsageStats 切换事件可能被跳过的问题：重叠查询最近 30 秒，只对真实应用边界更新去重水位，微信内部 Activity 切换不推进边界。
- 新增由用户主动授权的“增强保护”，即时监听窗口包名，使用可信的无障碍覆盖页。UsageStats 保留为补充检测；两者使用同一保护逻辑，避免重复问候和重复计时。
- 覆盖页显示异常不再直接终止全部监测，持续检查并重试。进程仍存活且增强服务已连接时，可独立维持已有冷静期，不依赖前台补充检测服务持续运行；不保证系统终止整个进程后仍然保护。
- 主页显示最近识别到的微信进入时间，以及未计入自动规则的原因。对小米 15 增加 MIUI 桌面包名回退和后台设置提示。小米真机后台策略仍需实测。

运行时不需要服务器、账号、网络或对象参与。APK 无联网权限，不修改微信 APK，不注入进程，不读取聊天、联系人、通知、输入框或密码。

## 安装与首次设置

安装 `outputs/WeChat-Cooldown-Lock-1.0.2-debug.apk`，打开“微信冷静锁”。在“保护设置”中依次阅读说明，主动授予：

1. **使用情况访问**：通过系统 UsageStatsManager 的应用包名与时间事件识别微信进入、离开和会话持续时间。
2. **显示在其他应用上层**：在微信上方显示情绪问候、冷静页或可收起的小入口。
3. **通知权限（Android 13+，可选）**：显示常驻监测通知及“一键冷静”操作。拒绝此权限不会自动获得权限；系统可能只在活动应用管理中显示前台服务。
4. **增强保护（建议开启）**：阅读用途说明后，在系统无障碍页面主动启用“微信冷静锁 · 增强保护”。只订阅窗口状态切换，`canRetrieveWindowContent=false`、`canPerformGestures=false`，不读取聊天、输入框、密码、通知，不截图，不执行手势。主页会显示服务是否实际连接。

若侧载应用被系统标为“受限设置”，须由用户在本应用详情中确认系统提供的授权入口后再启用；应用不能自行绕过系统限制。

返回主页，确认“本地监测正在运行”。两项必要权限已授予且全部监测未暂停时，应用在可见状态下启动前台服务；之后无需每次打开本应用。默认打开行为自动冷静。主页明确区分授权不足、后台未运行和监测正在运行。

“检查系统后台 / 电池限制”打开本应用详情，由用户自行检查厂商的后台管理。应用不自动改变电池策略，不要求关闭手机的系统安全措施。重启后会尝试恢复已经开启的监测；系统拒绝启动时，尝试显示点击恢复通知。强行停止应用、系统的活动应用停止操作和厂商限制都可能使恢复失效。

如曾安装旧版“停一下”并开启其无障碍服务，请先停用旧版保护，避免两套保护页同时出现。此项目使用独立包名，不覆盖旧应用，也不迁移旧记录。

## 情绪问候

从其他应用实际进入微信时问候一次：“现在的心情怎么样？”

| 选项 | 默认行为 |
| --- | --- |
| 😊 心情不错 | 撤下问候页，正常聊天 |
| 😐 有点烦躁 | 正常聊天，显示可收起的小型冷静入口 |
| 😠 我很生气 | 提供一键冷静和继续聊天；可设置为直接冷静 |
| 💔 害怕失去这段感情 | 提供一键冷静和继续聊天；可设置为直接冷静 |

不要求填写原因。微信内不同 Activity、聊天对象、朋友圈的切换按同一应用处理，不重复问候。系统临时窗口不视为离开微信。已在冷静期内时，冷静页优先，重新进入直接显示剩余时间。

## 自动触发规则

默认规则同时要求：

- 5 分钟滚动窗口内，符合条件的**重新进入**达到 3 次；首次进入不计重新进入。
- 每次计数的前一微信会话短于 60 秒，至少需要 2 次短会话。
- 离开微信至少 10 秒，短暂切换不累计风险。
- 离开微信时先返回桌面或打开微信冷静锁 App 的会话可以累计风险。直接进入浏览器等其他应用后的返回不累计，即使之后经过桌面，以免将微信外链返回计入。选择“心情不错”和一次不合格返回不会清空此前累计；主页分别显示窗口内累计次数和最近一次判断原因。

正常聊天若也出现相同的短会话和反复返回行为，仍可能触发。这些条件也可能漏掉部分冲动行为。规则无法识别真实情绪，不能保证正常聊天绝无误触发。不能仅凭打开次数认定情绪失控。触发原因会如实显示实际满足的行为条件，不宣称识别了情绪或辱骂。

长于或等于短会话上限的正常聊天会清空此前累计。微信内部页面切换不算新会话；单独的 ACTIVITY_PAUSED 不立即认定离开，须等其他应用进入前台后才确认。会话时间来自系统事件，是近似值。

所有门槛可在设置调整：窗口 1–30 分钟，重新进入 2–10 次，短会话上限 15–180 秒，短会话次数 2–10 次，离开时间 5–120 秒。请选择能在时间窗口内实际达到的组合；极高次数配合过长离开门槛可能无法触发。

敏感时段默认关闭，初始为 22:00—01:00，支持跨午夜。时段内将重新进入门槛降低 1 次，最低仍为 2 次，同时保留短会话次数和离开时间条件。问候频率不受影响。相同起止时间表示无有效时段。

风险累计仅存于服务内存，服务重启后重新累计，不重播历史使用事件来追溯锁定用户。

## 冷静锁与快捷入口

可选 5、10、20、30、60 分钟。自动触发默认 5 分钟，手动默认 20 分钟。冷静页显示剩余时间、原因、事实与担心的区分提醒，以及冲动记录入口。

截止时间保存于 DataStore。冷静期间反复打开微信或重复点击启动不会延期。当前开机周期使用单调时钟计时，不受调整日期影响；重启后使用有上限的本机日期回退，改日期可能导致提前结束或剩余时间变化，最长不超过原选时长。到期自动撤下保护页，不要求密码或点击解锁。保护页撤下先于到期历史写入。

应用内不提供提前结束当前冷静的操作。冷静到期自动解锁。应用不限制系统桌面、其他应用、系统设置或卸载；操作系统仍可关闭或撤销服务权限，不能宣称无法绕过。

快速启动不要求填写原因：

- 主页“一键冷静”。
- 长按应用图标的静态快捷方式，或主页请求固定到桌面。
- 常驻通知中的“一键冷静”。
- 快速设置面板的编辑菜单中添加“一键冷静”磁贴。Android 14+ 使用 PendingIntent 入口，旧版本使用受版本检查保护的旧 API。

## 本地记录和统计

独立文本框保存想发的话、所选情绪、时间和最近一次触发原因，没有发送、分享或导出功能。文本上限 6000 字符。草稿在本机保存，支持逐条删除问候与文字记录，或一次删除所有记录、统计和草稿。清除历史不取消当前冷静或修改设置。

情绪问候也会保存一条仅含情绪和时间的本地记录。记录页面展示最近 300 条情绪记录、100 次冷静；这些列表上限不等于自动删除上限。微信会话保留最近 2000 条，不保存其他应用的使用历史。近 7 天统计查询现存记录，按分钟刷新时间窗口；使用分钟数只包含监测捕获的已结束会话，不是系统的完整微信使用时长。

设置、截止时间和草稿使用 DataStore；文字记录、问候、冷静历史和微信会话使用 Room。存于应用私有目录，未另加应用层密码加密。禁用云备份和设备迁移，卸载会清除数据。界面使用 FLAG_SECURE，限制系统截图和任务预览；系统输入法仍有自己的数据处理策略。

## 权限与 Android 限制

基础检测使用 UsageStats 和 TYPE_APPLICATION_OVERLAY。主动授权增强保护后，额外使用只监听窗口切换的 AccessibilityService 及 TYPE_ACCESSIBILITY_OVERLAY；普通聊天内容不在访问能力范围内。系统的使用情况授权范围比“仅微信”更广，本应用只按包名和时间识别微信，其他应用包名只在内存中用于边界判断。增强服务由系统的 BIND_ACCESSIBILITY_SERVICE 签名权限保护。

| 权限 | 用途 |
| --- | --- |
| PACKAGE_USAGE_STATS | 用户在系统页面主动授予使用情况访问 |
| SYSTEM_ALERT_WINDOW | 用户主动允许悬浮问候与临时保护页 |
| FOREGROUND_SERVICE / FOREGROUND_SERVICE_SPECIAL_USE | 可见的本地保护前台服务；声明具体 specialUse 用途 |
| POST_NOTIFICATIONS | Android 13+ 的可选通知和快捷入口 |
| RECEIVE_BOOT_COMPLETED | 在系统允许时尝试恢复用户已开启的监测 |

不申请网络、联系人、相机、麦克风、位置、短信或读取存储权限。

AndroidX 还生成一项应用内部的签名级动态接收器权限，用于保护本应用接收器，不需要用户另行授权，也不授予读取微信的能力。

屏幕亮起时约每 350 毫秒补充查询一次，熄屏时放慢；增强保护直接监听系统窗口事件。保护覆盖页约每 250 毫秒核对已有截止时间并重试显示。系统仍可能延迟事件或关闭服务，保护不保证零延迟。首次接入或恢复 UsageStats 查询用最近 30 分钟的最新前台事件建立基线；系统没有提供近期事件时，可能需要下一次实际应用切换才能识别。

小米 15：建议开启增强保护，并在系统应用详情检查后台自启动、电池限制及服务连接状态，具体菜单依 HyperOS 版本而异。小米提供的[无障碍功能说明](https://www.mi.com/global/support/faq/details/KA-728047/)也注明菜单路径因版本和型号而异，可在“已下载的应用”中查找服务。快速切出不足默认 10 秒会继续问候，但不累计自动触发次数；主页会解释未累计原因。若要测试自动锁，请按完整组合门槛测试，不要只快速连点打开。

以下路径不保证覆盖：通知快捷回复、所有分屏/小窗、使用不同包名的微信分身、其他设备、权限撤销、强行停止、系统停止前台服务、厂商后台限制、使用事件缺失或延迟。服务和计时不采用锁设备、篡改微信、禁止卸载或持续唤醒屏幕的方式维持保护。不能保证完全拦住发送，也不能保证永久后台运行。

技术参考：[UsageEvents](https://developer.android.com/reference/android/app/usage/UsageEvents.Event)、[UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager)、[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[悬浮窗口类型](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY)、[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。

## 项目架构与构建

```text
app/   Compose 页面、GuardViewModel、UsageStats 源、前台服务、悬浮窗口、快捷入口
data/  DataStore 设置、Room 实体/DAO/数据库、CooldownRepository
core/  纯 Kotlin 行为引擎、设置模型、时段与截止时间计算
```

应用通过共享 Repository 提供状态；ViewModel 管理页面和操作，Compose 观察 StateFlow；服务独立观察前台事件并调用同一 Repository。核心算法不依赖 Android，也不涉及聊天内容。

Android Studio 打开本目录，安装 SDK 36 / Build Tools 36.0.0。AGP 9.0.1、Gradle 9.1.0、内置 Kotlin 2.2.10、Compose Compiler 2.2.10、KSP 2.3.4。Java 源码目标 17，构建使用支持 Gradle 9.1 的 JDK，建议 JDK 21。当前已在本机 JDK 25 上构建。

```powershell
.\gradlew.bat :app:assembleDebug :core:test :data:testDebugUnitTest :app:testDebugUnitTest :app:lintDebug
```

macOS / Linux 可用 `bash ./gradlew` 执行相同任务。配置 Android SDK 路径至本机 `local.properties`，不要提交此文件。首次构建需要联网获取构建依赖，APK 运行不联网。

`build.ps1` 是本机辅助脚本，使用已安装工具链，将构建复制到临时 ASCII 路径，避免 Windows 中文路径的 Java 工作进程编码问题；支持 `JAVA_HOME`、`ANDROID_HOME` 和 `-Offline`。构建结果、报告和预览复制到 `outputs/`。Room 的导出 schema 随源码提供，后续升级数据库必须编写迁移，未使用破坏性迁移回退。

## 测试结果与真机验收

当前自动化测试、构建和签名结果见 [TESTING.md](TESTING.md)。桌面模拟覆盖 Android 10、13、15；不等于在这些系统的实体手机上完成微信联动。

本机没有连接 Android 手机或模拟器，未进行厂商真机后台存活、耗电、重启自启和真实微信覆盖验证，不伪造这些结果。

建议在自己的手机按以下步骤验收：

1. 完成权限设置，确认主页“本地监测正在运行”。
2. 从桌面进入微信选择“心情不错”，正常聊天；切换聊天对象和朋友圈不应重复问候。
3. 短暂切到其他应用再返回，应有新问候，但不计入自动风险。
4. 从微信直接打开外部页面后返回，不应累计风险。长聊超过 60 秒，应清空默认风险累计。
5. 默认规则：进入微信使用约 15 秒，回桌面停留约 15 秒再进入，连续做 3 次重新进入。约 90 秒内达到 3 次合格重新进入，应启动 5 分钟冷静；首次进入不计重新进入。
6. 冷静中回桌面后重进微信，应显示同一截止时间；到期自动撤下，无须点击解锁。
7. 验证冷静页没有提前结束按钮，冷静期内首页不提供暂停全部监测；测试通知按钮、图标快捷方式、快速设置磁贴，以及记录保存、重开查看和删除。
8. 在 Xiaomi/HyperOS、OPPO/ColorOS、vivo/OriginOS、Samsung/One UI 和其他实际使用设备上分别检查锁屏/解锁、划掉任务、电池限制、重启及系统停止服务后的状态。每台设备独立记录结果，不把一种系统的成功推广到所有厂商。
